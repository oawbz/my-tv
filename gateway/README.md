# M3U / HLS 转发网关

Go + Gin 服务。运行时只读取一个 IPTV M3U 播放列表（本地文件或 HTTP URL），将同名频道的多个播放源合并。`GET /channels.json` 输出 Android 应用使用的 `version: 1` 格式，每个频道只有一个网关播放地址，台标也经网关代理。

输出频道固定为当前 `https://awbz.cn/tv/channels.json` 的 50 个预设台及其顺序，顺序保存在 `order.go`。频道名称不变时网关播放 URL 保持稳定；源数量和台标随 M3U 刷新，频道在失去全部有效源时会从 JSON 中隐藏。M3U 中没有有效播放源的预设台自动隐藏；M3U 中其他台不输出。解析时会跳过格式错误或播放 URL 无效的条目，不影响其他台。

每次请求频道播放地址时都会并发探测该台的多个源，按首次收到数据的耗时排序；短时间内的并发测速合并为一次上游请求。源打不开、HLS 清单无有效播放地址时尝试下一源，并暂时避开失败源；子清单或分片失败后，下一次请求频道播放清单也会选用其他源。HLS 子清单、分片和密钥地址会改写为短期有效的网关地址。多个设备同时请求同一上游 URL 时，HLS 清单与分片共享下载；清单缓存 1 秒，分片和密钥缓存 5 分钟（单对象最多 8 MiB、总缓存最多 128 MiB）。持续直播流由一条上游连接向同时观看的设备分发；最后一个设备离开时关闭上游连接。台标也使用共享缓存；缺失、获取失败或不是可用位图时返回默认 PNG 图标。

## 启动与配置

```sh
cd gateway
go run .
```

已有可执行文件可在该目录运行 `go build -o gateway .` 更新，然后重启 `./gateway`。服务使用 Gin Release 模式；为兼容会在空闲连接上发送异常重定向的上游，网关不会复用上游 HTTP 空闲连接。共享清单、分片缓存和直播流分发仍会合并多个设备的请求。

首次运行会在当前目录自动生成 `config.json`，以后直接运行同一命令即可。默认配置如下：

```json
{
  "listen": "0.0.0.0:2219",
  "m3u": "./index.m3u",
  "public_base": "",
  "cache_duration": "3h",
  "user_agent": "AptvPlayer/1.4.0"
}
```

把 M3U 放到 `gateway/index.m3u`，或修改 `m3u` 为其他本地路径或远程 URL。`public_base` 留空时使用请求的主机名自动生成播放与台标地址，局域网内可以直接访问。通过带 `/tv` 前缀的反向代理部署到 `awbz.cn` 时，把它设为 `https://awbz.cn/tv`。修改配置后重启服务。`config.json` 和 `index.m3u` 已加入 Git 忽略列表，以免误提交播放凭据。没有 M3U 时服务仍会启动，`/healthz` 显示零个频道；收到频道列表请求后才会尝试读取。

如果用反向代理，请把 `/tv/` 去掉前缀后转给 `:2219`，并允许视频长时间流式传输：

```nginx
location /tv/ {
    proxy_pass http://127.0.0.1:2219/;
    proxy_buffering off;
    proxy_read_timeout 1h;
}
```

远程 M3U 在首次请求 `channels.json` 或播放地址时获取，成功后默认缓存三小时。缓存过期不会主动请求；下一次频道列表或播放请求才刷新，期间没有定时器或轮询。若该台的所有缓存源在缓存期内失效，播放请求会立即重新获取 M3U 并用新源重试一次。刷新失败会继续提供上次成功的列表，并在 30 秒后由下一次访问重试。`cache_duration` 可改为 `30m`、`6h` 等正时长。本地 M3U 在频道列表请求时重新读取。所有上游请求（M3U、测速、视频、分片和台标）使用 `user_agent`，可按上游要求修改。每次播放请求都会选源，临近的并发请求复用测速，因此换台可能需要数秒。`GET /healthz` 返回当前频道数。HLS 分片地址保存在单实例内存中，重启后旧播放清单需要重新获取。上游 URL 签名过期、IP 白名单限制或 DRM 加密仍可能导致无法播放；网关不会绕过上游授权。

```sh
go test ./...
python3 ../scripts/validate_channels.py http://127.0.0.1:2219/channels.json
```

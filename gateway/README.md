# M3U / HLS 转发网关

Go + Gin 服务。运行时读取一个或多个 IPTV M3U 播放列表（本地文件或 HTTP URL），将同名频道的多个播放源合并。`GET /channels.json` 输出 Android 应用使用的 `version: 1` 格式，`GET /channels.m3u` 输出通用 IPTV M3U 播放列表。每个频道只有一个网关播放地址，台标也经网关代理。

输出频道由 `config.json` 中的 `channels` 列表决定。首次生成的列表沿用原有排序，删除了 CCTV5+，共 49 个台。可以增删频道或调整顺序；没有有效 M3U 播放源的频道自动隐藏，未列入配置的频道不输出。若设置为 `"channels": []`，则按上游 M3U 的顺序输出全部有效频道，保留上游名称、分组、`tvg-id` 和台标；多个上游中名称相同的频道合并播放源，名称不同的条目分别输出。两种模式都通过网关代理播放和台标，不直接暴露上游播放地址。解析时会跳过格式错误或播放 URL 无效的条目，不影响其他台。频道 `id` 决定预置模式下稳定的网关播放地址，修改显示名称不会改变该地址；空列表模式下播放地址由上游频道名称决定。

频道在最近 5 分钟内成功播放过时，下一次请求直接尝试该源；单源频道也直接请求播放地址，不做额外探测。多源频道没有近期成功记录时才并发探测，并立即尝试最先响应的源，不等待其余慢源；临近请求合并同一上游的探测。源打不开、HLS 清单无有效播放地址时尝试下一源，并暂时避开失败源。HLS 子清单、分片和密钥地址会改写为短期有效的网关地址。已有播放清单中的资源始终取自同一上游；资源失败或超时后暂时避开该源，由播放器重新请求频道入口时选择备用源，不直接拼接两路 HLS 分片。网关还会按 `#EXTINF` 记录实际分片下载时间；连续三个分片耗时超过播放时长的 1.5 倍（最低阈值 3 秒）才降低该源优先级。检查只使用真实转发请求，不额外轮询。多个设备同时请求同一上游 URL 时，HLS 清单与分片共享下载；清单缓存 1 秒，分片和密钥缓存 5 分钟（单对象最多 8 MiB、总缓存最多 128 MiB）。持续直播流由一条上游连接向同时观看的设备分发；最后一个设备离开时关闭上游连接。台标也使用共享缓存；缺失、获取失败或不是可用位图时返回默认 PNG 图标。

## 启动与配置

冷切台时，以 `.m3u8` 结尾的 HLS 地址只获取一次清单：探测成功后将清单交给现有共享缓存，选中该源即可直接返回。其他类型地址仍使用原来的短请求探测。

```sh
cd gateway
go run .
```

已有可执行文件可在该目录运行 `go build -o gateway .` 更新，然后重启 `./gateway`。服务使用 Gin Release 模式；为兼容会在空闲连接上发送异常重定向的上游，网关不会复用上游 HTTP 空闲连接。共享清单、分片缓存和直播流分发仍会合并多个设备的请求。

在局域网设备上打开 `http://网关IP:2219/`，首页会显示 M3U 和 JSON 订阅地址；若已启用鉴权，先在首页输入 token 生成连接。支持 M3U 订阅的播放器使用 `/channels.m3u`，本项目客户端使用 `/channels.json`。请用网关的局域网 IP 打开首页，这样生成的地址也能供其他设备访问。

首次运行会在当前目录自动生成 `config.json`，以后直接运行同一命令即可。下面节选默认配置中的前两个频道，实际文件会生成完整的 49 个频道：

```json
{
  "listen": "0.0.0.0:2219",
  "m3u_sources": ["./index.m3u"],
  "channels": [
    {"id": "CCTV1 综合", "name": "", "group": "央视", "aliases": ["CCTV-1高清"], "logo": ""},
    {"id": "CCTV2 财经", "name": "", "group": "央视", "logo": ""}
  ],
  "tokens": [],
  "cache_duration": "3h",
  "user_agent": "AptvPlayer/1.4.0"
}
```

把 M3U 放到 `gateway/index.m3u`，或在 `m3u_sources` 中填写一个或多个本地路径或远程 URL。配置文件必须包含非空的 `m3u_sources` 和 `channels` 列表；旧的 `m3u` 和 `channel_aliases` 字段会在启动时报错。所有上游都按 `#EXTM3U` 播放列表解析。台名不一致时，在对应频道的 `aliases` 中填写上游台名，例如：

```json
"m3u_sources": ["./index.m3u", "https://example.com/other.m3u"],
"channels": [
  {"id": "CCTV1 综合", "name": "中央一套", "group": "央视", "aliases": ["CCTV-1高清"], "logo": "https://example.com/cctv1.png"},
  {"id": "河北卫视", "group": "地方卫视", "aliases": ["河北台"], "logo": ""}
]
```

`id` 必填且不能重复；`name` 可省略或留空，此时显示 `id`。`aliases` 是不同上游对这个台使用的其他名称。`id`、`name` 和别名都能匹配 M3U 台名；名称冲突会被拒绝。`group` 可省略，此时使用匹配到的上游分组。`logo` 留空时使用上游台标，上游台标不存在或获取失败时显示默认图标；填写 `logo` 时优先使用该地址，获取失败也显示默认图标。播放、资源与台标地址根据访问网关时使用的主机名生成，在局域网内直接访问 `http://网关IP:2219/channels.json`。修改 `channels` 后下一次列表、播放或台标请求会加载新列表；配置无效时保留上一份有效列表。监听地址、M3U 源、缓存时间、UA 和 token 的修改需要重启。`config.json` 和 `index.m3u` 已加入 Git 忽略列表，以免误提交播放凭据。没有 M3U 时服务仍会启动，收到频道列表请求后才会尝试读取。

`tokens` 留空或省略时不启用鉴权。需要鉴权时可配置多个值，例如 `"tokens": ["device-one-secret", "device-two-secret"]`。启用后，除首页外的所有接口都要求 URL 查询参数 `toke`，例如 `http://网关IP:2219/channels.m3u?toke=device-one-secret`；缺失或错误会返回 HTTP 401。在首页输入有效 token 可生成 M3U 和 JSON 的可用连接。JSON、M3U 和 HLS 清单中的播放、台标、子清单、密钥与分片地址会自动携带相同 token。鉴权后的响应不使用共享 HTTP 缓存。token 会出现在订阅和播放 URL 中，请只向需要访问的设备提供这些连接。

每份远程 M3U 在首次请求 `channels.json` 或播放地址时获取，成功后各自默认缓存三小时。缓存过期不会主动请求；下一次频道列表或播放请求才刷新，期间没有定时器或轮询。若该台的所有缓存源在缓存期内失效，播放请求会立即重新获取 M3U 并用新源重试一次。某份远程 M3U 刷新失败时保留该份上次成功的列表，并在 30 秒后由下一次访问重试。`cache_duration` 可改为 `30m`、`6h` 等正时长。本地 M3U 在频道列表请求时重新读取。所有上游请求（M3U、测速、视频、分片和台标）使用 `user_agent`，可按上游要求修改。HLS 分片地址保存在单实例内存中，重启后旧播放清单需要重新获取。上游 URL 签名过期、IP 白名单限制或 DRM 加密仍可能导致无法播放；网关不会绕过上游授权。

```sh
go test ./...
python3 ../scripts/validate_channels.py http://127.0.0.1:2219/channels.json
```

远程 M3U 缓存过期且已有频道数据时，播放请求会立即使用现有数据，并由这次访问触发一次后台刷新；仅配置远程 M3U 时，频道列表请求也采用这一方式。同时到来的请求共用这一轮刷新。首次加载仍同步等待结果，播放失败后的强制修复也同步执行。包含本地 M3U 的配置在请求频道列表时仍同步读取本地文件。后台刷新独立于触发它的客户端连接，最多运行 30 秒；没有访问时不会启动。
